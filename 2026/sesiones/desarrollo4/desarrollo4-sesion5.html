Sesión 5 — CSS: Frameworks de Componentes con Bootstrap

Hasta ahora escribimos todo el CSS a mano (Flexbox, Grid). Hoy conocemos Bootstrap: un framework que ya trae resuelto un sistema de grilla (row, col) y componentes visuales listos para usar (tarjetas, barras de navegación, modales), acelerando muchísimo el maquetado.

Objetivos de aprendizaje

Al finalizar esta sesión, vas a poder:

  • Explicar qué es un framework CSS y por qué acelera el maquetado frente a escribir CSS 100% propio.
  • Vincular Bootstrap a un proyecto mediante CDN (hoja de estilos + script).
  • Aplicar el sistema de grilla clásico de 12 columnas con container, row y col-*.
  • Construir layouts responsivos combinando clases de columna por breakpoint (col-12 col-md-6 col-lg-3).
  • Reutilizar componentes preestablecidos: navbar, cards y modal, entendiendo qué hace cada clase y atributo data-bs-*.
  • Maquetar la interfaz de un panel de administración o catálogo vacío usando exclusivamente clases de Bootstrap.

¿Qué es un framework CSS (y qué es Bootstrap)?

Un framework CSS es una biblioteca de estilos y componentes ya escritos por otro equipo de desarrolladores, que nosotros importamos y reutilizamos agregando clases a nuestro HTML. Bootstrap es el framework CSS más usado del mundo: nació en Twitter en 2011 y hoy está en su versión 5.

Las Clases en Bootstrap son etiquetas de CSS predefinidas que se aplican directamente a los elementos HTML para darles diseño, estructura y funcionalidad de forma inmediata

CSS propio (Flexbox/Grid, Sesiones 3 y 4)Bootstrap
Quién escribe el CSSNosotros, línea por líneaEl equipo de Bootstrap; nosotros solo agregamos clases
Velocidad de maquetadoMás lenta, pero con control totalMuy rápida: componentes ya resueltos
PersonalizaciónTotal, sin límitesLimitada al sistema de clases del framework (aunque se puede sobrescribir)
Curva de aprendizajeHay que entender CSS a fondoHay que memorizar el "vocabulario" de clases del framework
Analogía
Escribir CSS propio con Flexbox/Grid es como cocinar un plato desde cero, eligiendo cada ingrediente. Usar Bootstrap es como comprar ingredientes semi-preparados (una salsa lista, una masa ya amasada): cocinás mucho más rápido, aunque el sabor final está un poco más "estandarizado" por el fabricante. Los buenos desarrolladores saben elegir cuándo conviene cada opción, e incluso combinarlas en el mismo plato.
¿Entonces todo lo anterior no sirvió?
Al contrario: entender Flexbox y Grid a fondo (Sesiones 3 y 4) es lo que te permite hoy entender qué está pasando realmente detrás de las clases de Bootstrap. Bootstrap usa Flexbox internamente para su sistema de grilla — no es magia, es el mismo CSS que ya conocés, empaquetado en clases reutilizables.

Instalación de Bootstrap vía CDN

Un CDN (Content Delivery Network) es un servicio externo que ya tiene alojados los archivos de Bootstrap. En vez de descargar nada, simplemente enlazamos esas URLs desde nuestro index.html.

->Link a pagina oficial de framework Bootstrap
->Video introductorio a Bootstrap (Youtube)
index.html (fragmento del head y antes de </body>) 
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>TecnoStore - Panel</title>

    <!-- 1. Hoja de estilos de Bootstrap: SIEMPRE en el head -->
    <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body>

    <!-- ... todo el contenido de la página ... -->

    <!-- 2. Bundle de JS de Bootstrap (incluye Popper): SIEMPRE
         al FINAL del body, justo antes de cerrar </body>.
         Es necesario para que funcionen navbar colapsable, modal, etc. -->
    <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>
</body>
</html>
Orden importa
El CSS va en el <head> (se necesita antes de pintar la página). El script de JS va al final del <body>: si lo ponés en el <head>, el navegador intenta ejecutarlo antes de que exista el HTML que necesita manipular, y componentes como el navbar colapsable o el modal no van a funcionar.

La lógica del sistema de grilla clásico: 12 columnas

Bootstrap divide el ancho disponible en 12 columnas imaginarias e iguales. Nosotros no dibujamos esas 12 columnas: solo le decimos a cada elemento "cuántas de esas 12 columnas quiero ocupar", con clases como col-4, col-6, col-8, etc.

NivelClase / etiquetaFunción
1<div class="container"> o "container-fluid"Envoltorio exterior que centra el contenido y le da márgenes laterales. container-fluid ocupa el 100% del ancho de pantalla; container tiene un ancho máximo con márgenes automáticos.
2<div class="row">Una fila de la grilla. Es un contenedor Flexbox interno de Bootstrap: sus hijos directos se acomodan en horizontal.
3<div class="col-4">Una columna dentro de la fila, que ocupa 4 columnas de las 12 unidades disponibles (es decir, 4/12 = 33% del ancho de la fila).
ejemplo-grid-basico.html 
<div class="container">
    <div class="row">
        <div class="col-4">Columna A (4/12 = 33%)</div>
        <div class="col-4">Columna B (4/12 = 33%)</div>
        <div class="col-4">Columna C (4/12 = 33%)</div>
    </div>
</div>
<!-- 4 + 4 + 4 = 12 → las tres columnas llenan exactamente la fila -->
Analogía
Pensá la fila (row) como una torta cortada siempre en 12 porciones iguales, sin importar el tamaño real de la torta. Si decís col-4, estás pidiendo "4 porciones" (un tercio de la torta). Si decís col-6, pedís "6 porciones" (la mitad). Mientras la suma de porciones pedidas en la fila no supere 12, todo entra prolijamente en una sola fila.
¿Qué pasa si pido más de 12?
Si en una misma fila la suma de columnas supera 12 (por ejemplo, cuatro col-4 = 16), Bootstrap no rompe el diseño: la columna "sobrante" salta automáticamente a una nueva línea, como si fuera un renglón nuevo de la torta. Es un comportamiento seguro, pero conviene evitarlo para que el diseño sea prolijo y predecible.

Breakpoints responsivos: el "infijo" en el nombre de la clase

Cada clase de columna puede llevar un infijo que indica a partir de qué ancho de pantalla aplica esa cantidad de columnas. Sin infijo, la regla aplica siempre (mobile-first).

ClaseAncho mínimo de pantallaDispositivo típico
col-*0px (siempre, sin condición)Cualquier pantalla, incluida la más chica
col-sm-*≥ 576pxCelulares en horizontal
col-md-*≥ 768pxTablets
col-lg-*≥ 992pxNotebooks / escritorio
col-xl-*≥ 1200pxMonitores grandes
col-xxl-*≥ 1400pxMonitores muy grandes
Filosofía "mobile-first"
Bootstrap se diseña pensando primero en el celular y después "agranda" la pantalla: por eso col-12 col-md-6 col-lg-3 se lee como "por defecto (en cualquier pantalla) ocupá las 12 columnas completas; a partir de md, ocupá solo 6; a partir de lg, ocupá solo 3". Cada breakpoint sobrescribe al anterior a partir de ese ancho mínimo, nunca antes.

Componentes preestablecidos: navbar, cards y modal

Además de la grilla, Bootstrap trae componentes visuales completos: solo hay que copiar la estructura HTML sugerida y agregar las clases correspondientes.

Navbar (barra de navegación)

Clase / atributoFunción
navbar navbar-expand-lgActiva el componente; expand-lg indica que se colapsa en un botón hamburguesa por debajo de "lg" (992px).
navbar-brandEl logo o nombre de marca dentro del navbar.
navbar-toggler + data-bs-toggle="collapse"El botón hamburguesa que aparece en pantallas chicas y abre/cierra el menú.
collapse navbar-collapseEl contenedor de los enlaces que se oculta/muestra según el ancho de pantalla.

Card (tarjeta)

ClaseFunción
cardContenedor con borde, esquinas redondeadas y sombra sutil ya definidos.
card-img-topImagen que ocupa todo el ancho superior de la tarjeta.
card-bodyZona de contenido con padding interno ya calculado.
card-title / card-textEstilos tipográficos ya definidos para el título y el texto de la tarjeta.

Modal (ventana emergente)

Clase / atributoFunción
data-bs-toggle="modal"Se agrega al botón que abre el modal.
data-bs-target="#miModal"Indica qué modal abrir, por su id.
modal fadeClases del contenedor raíz del modal; fade agrega una transición suave de aparición.
modal-dialog / modal-contentEstructura interna: tamaño de la ventana y su contenido visual (borde, fondo).
data-bs-dismiss="modal"Se agrega a un botón dentro del modal para cerrarlo.
Analogía
Los atributos data-bs-* son como controles remotos con nombre de canal: el botón "abrir" tiene el atributo data-bs-target="#modalDemo", que es literalmente el "canal" (id) al que apunta. Bootstrap, con su JavaScript ya escrito, "escucha" esos controles remotos y hace aparecer o desaparecer la ventana correspondiente.

El grid de Bootstrap vs. Flexbox/Grid CSS puro (Sesiones 3 y 4)

Es fundamental entender que el row/col de Bootstrap no es un tercer sistema de maquetado distinto: por debajo, Bootstrap usa Flexbox (lo que vimos en la Sesión 3) para acomodar las columnas dentro de cada fila.

CSS Grid puro (Sesión 4)Grid de Bootstrap (row/col)
Motor realdisplay: grid nativo del navegadordisplay: flex nativo, "disfrazado" con clases row/col-*
Unidad de medidaCualquiera: fr, px, %, minmax()Fija: siempre "de 12", con clases predefinidas
Cuándo convieneLayouts complejos y muy personalizadosPrototipos rápidos, paneles administrativos, formularios estándar
No es "uno mejor que el otro"
Muchos proyectos reales usan Bootstrap para la estructura general (navbar, grilla de formularios, cards) y CSS Grid propio para secciones muy específicas que necesitan mayor control (por ejemplo, un dashboard con áreas irregulares). Saber ambos te da flexibilidad para elegir la herramienta correcta según el caso.

Detectá el error: código para corregir en VSC

Copiá estos fragmentos en VSC (recordá vincular el CDN de Bootstrap) y usá el Inspector (F12) y la Console para encontrar los errores.

Con errores

Ejercicio 1 — Grid clásico

buggy-9.html 
<div class="container">
  <div class="col-6">Columna A</div>
  <div class="col-6">Columna B</div>
</div>

<div class="container">
  <div class="row">
    <div class="column-4">Producto 1</div>
    <div class="column-4">Producto 2</div>
    <div class="column-4">Producto 3</div>
  </div>
</div>

🔎 Ninguna de las dos grillas se ve como columnas lado a lado. Encontrá los 2 problemas.

Ver solución y explicación
  1. En el primer bloque, las columnas .col-6 están directamente dentro de .container, sin un .row envolvente. El sistema de grilla de Bootstrap requiere siempre la jerarquía container > row > col-*; sin el .row, las columnas no reciben el display: flex necesario y se apilan una debajo de la otra.
  2. En el segundo bloque, la clase se escribió column-4 en vez de col-4. Como esa clase no existe en Bootstrap, el navegador simplemente la ignora (no tira error) y los elementos se comportan como bloques normales de ancho completo, apilados verticalmente.

Tip de debugging: en el Inspector, seleccioná el elemento y mirá el panel Styles: si una clase escrita en el HTML no aparece resaltada en ningún bloque de reglas CSS aplicadas, es señal de que esa clase no existe en la hoja de estilos cargada (typo).

Con errores

Ejercicio 2 — Modal que no abre

buggy-10.html 
<button type="button" class="btn btn-primary" data-bs-toggle="modal" data-bs-target="modalProducto">
  Ver producto
</button>

<div class="modal fade" id="modalProd">
  <div class="modal-dialog">
    <div class="modal-content">
      <div class="modal-body">Detalle del producto</div>
    </div>
  </div>
</div>

🔎 Al hacer clic en el botón, no pasa absolutamente nada. Encontrá 2 problemas (y no es que falte el script de Bootstrap).

Ver solución y explicación
  1. El botón usa data-bs-target="modalProducto": le falta el símbolo # al principio. Los selectores de data-bs-target siempre deben empezar con # para indicar "buscá por id", igual que en CSS.
  2. Aunque tuviera el #, el valor sería #modalProducto, pero el id real del modal es modalProd. Los nombres deben coincidir exactamente, letra por letra.

Tip de debugging: en la Console del Inspector no siempre aparece un error visible para este caso (Bootstrap simplemente no encuentra el elemento y no hace nada). Es mejor usar la pestaña Elements, hacer Ctrl+F y buscar el id exacto para confirmar que coincide letra por letra con el data-bs-target.
