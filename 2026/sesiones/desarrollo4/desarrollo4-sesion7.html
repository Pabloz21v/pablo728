¿Qué vamos a construir, exactamente?
Un catálogo de productos (igual en espíritu al que ya maquetaste en las Sesiones 3 a 6) que: (1) se dibuja solo a partir de un array de objetos JavaScript, (2) se puede buscar por nombre y filtrar por categoría, (3) tiene un formulario para agregar productos nuevos, (4) permite editar cualquier producto existente, y (5) permite eliminarlo con confirmación. Orden de los scripts
Los <script> van al final del <body> (igual que vimos con Bootstrap en la Sesión 5): así el HTML ya existe en el DOM cuando JavaScript intenta buscarlo con querySelector. Si los ponés en el <head> sin más cuidado, muchas veces JS no va a encontrar los elementos todavía y vas a obtener null.

Cómo se enlazan HTML, CSS y JavaScript

Ya sabés seleccionar elementos del DOM y escuchar eventos. Pero queda la pregunta que más traba cuando se arma la primera web: ¿dónde escribo cada cosa y cómo hago que este botón haga algo? Un botón no "sabe" JavaScript: hay que cablearlo. En esta sección vas a ver el cableado completo, pieza por pieza, y con una demo real incluida en esta misma página.

La idea en una frase
HTML es la estructura, CSS la apariencia y JS el comportamiento. Se comunican por dos canales y solo dos: el atributo class conecta HTML con CSS, y el atributo id conecta HTML con JavaScript. Si los nombres no coinciden exactamente, el enlace no existe: no aparece ningún error de sintaxis, simplemente no pasa nada.

Las rutas tienen que existir
href="estilos.css" significa "en la misma carpeta que este HTML". Si tu CSS está dentro de una carpeta css/, la ruta correcta es href="css/estilos.css", y si el JS está en js/, entonces src="js/app.js". Abrí F12 → pestaña Network y recargá: si ves un 404 en estilos.css o app.js, el navegador está buscando el archivo en un lugar donde no está — y por eso "no funciona nada".

2. El contrato de nombres: id y class

Un mismo elemento HTML tiene dos identificadores, y cada uno le habla a un lenguaje distinto. Mirá el mismo botón visto desde los tres archivos:

un mismo nombre escrito en los tres archivos 
<!-- 1) HTML: el botón lleva id (para JS) y class (para CSS) -->
<button id="btn-saludar" class="btn-primario">Saludar</button>

/* 2) CSS: se engancha por la CLASE, con un punto delante */
.btn-primario {
  background: #4fd1c5;
  color: #06141a;
  border-radius: 8px;
}
.btn-primario:hover { filter: brightness(1.1); }

// 3) JS: se engancha por el ID, con una almohadilla delante
const boton = document.querySelector('#btn-saludar'); // ← mismo nombre, sin class

boton.addEventListener('click', () => {
  // acá va lo que tiene que pasar al tocar el botón
});
La regla del nombre exacto
En el HTML escribís id="btn-saludar" (sin símbolos). En JavaScript lo buscás como '#btn-saludar' (con #). En el HTML escribís class="btn-primario". En CSS lo estilás como .btn-primario (con .). Es el mismo criterio que ya usás para los selectores CSS desde la Sesión 1: # es id y . es class.

3. Qué propiedad de JS lee cada control de HTML

Esta es la tabla que resuelve el 90% de las dudas de "cómo conecto el HTML con JS". Cada control tiene una propiedad para leerlo y un evento que avisa cuándo cambió:

Elemento HTMLCómo lo leo / modificoEvento típico
<button id="btn">document.querySelector('#btn') y le agrego un listener (no se "lee" ningún valor: solo se escucha el click).click
<input type="text">input.value — el texto escrito, siempre como string.input (cada tecla) / change (al salir del campo)
<input type="number">input.value + parseFloat() o parseInt() para convertirlo en número.input / change
<input type="checkbox">input.checked — true o false.change
<select>select.value — el value de la <option> elegida.change
<textarea>textarea.value — el texto completo del área.input
<form>form.addEventListener('submit', …) + event.preventDefault() como primera línea.submit
<h3>, <p>, <span>el.textContent = 'texto' — escribe el contenido (seguro, no interpreta HTML).—
<img>img.setAttribute('src', url) y img.setAttribute('alt', texto).—
Cualquier elementoel.classList.add('x') / .remove('x') / .toggle('x') — así JS activa una regla CSS.—

4. La receta de 4 pasos para conectar cualquier control

No hace falta memorizar nada más: todos los enlaces de esta sesión (y de tu proyecto final) siguen siempre los mismos cuatro pasos.

  1. 1
    Poné un id en el HTML A cada elemento que JS tenga que encontrar: <button id="btn-saludar">. El id es único: no se repite en la página.
  2. 2
    Traé el elemento con querySelector const boton = document.querySelector('#btn-saludar'); — mismo nombre, con #. Se hace una sola vez, al inicio del archivo.
  3. 3
    Escuchá el evento con addEventListener boton.addEventListener('click', () => { … }); — el código de adentro no corre ahora, corre cuando el usuario actúa. Ese es el enlace.
  4. 4
    Dentro del callback: leé el input y escribí el DOM Leés con input.value, cambiás con salida.textContent y activás una clase CSS con salida.classList.add('destacado').

5. El ciclo completo: qué pasa cuando el usuario hace clic

#Quién actúaQué ocurre
1HTMLEl navegador lee el archivo y construye el árbol del DOM. Cada id queda registrado.
2CSSAplica un estilo a cada elemento según su class/selector. El botón se ve como botón.
3JSAl cargar, busca los elementos por id y les cuelga un addEventListener. Ahí queda "cableado".
4UsuarioHace clic. El navegador emite el evento click sobre ese elemento.
5JSSu callback se ejecuta: lee .value, calcula, y escribe en el DOM (textContent, classList, createElement).
6CSSEl navegador repinta solo la parte que cambió, aplicando los estilos correspondientes al nuevo contenido o a la nueva clase.
Por qué conviene cambiar clases y no estilos sueltos
Cuando JS hace salida.classList.add('destacado'), los colores y tamaños siguen viviendo en el CSS. Si mañana querés cambiar el diseño, editás una sola regla CSS y todos los elementos cambian. Si en cambio hacés salida.style.background = '#4fd1c5' desde JS, el estilo queda "incrustado" en el archivo equivocado y se vuelve difícil de mantener. Regla práctica: JS decide cuándo, CSS decide cómo se ve.

app.js 
// PASO 1 — ESTADO: una variable que guarda el dato real
let valor = 0;

// PASO 2 — GANCHOS: traigo los elementos del HTML por su id (una sola vez)
const pantalla = document.querySelector('#valor');
const btnMas   = document.querySelector('#btn-mas');
const btnMenos = document.querySelector('#btn-menos');
const btnReset = document.querySelector('#btn-reset');
const inputPaso = document.querySelector('#paso');

// PASO 3 — RENDER: la única función que escribe en el DOM
function pintar() {
  pantalla.textContent = valor;                                  // escribe el número
  pantalla.classList.toggle('negativo', valor < 0);              // activa CSS si es negativo
}

// PASO 4 — EVENTOS: cada control queda cableado a una acción
btnMas.addEventListener('click', () => {
  valor += leerPaso();   // lee el input y suma
  pintar();              // vuelve a dibujar
});

btnMenos.addEventListener('click', () => {
  valor -= leerPaso();
  pintar();
});

btnReset.addEventListener('click', () => {
  valor = 0;
  pintar();
});

// Lee el input y devuelve un NÚMERO (los inputs siempre dan texto)
function leerPaso() {
  const n = parseInt(inputPaso.value, 10);
  return isNaN(n) || n < 1 ? 1 : n;   // si no es válido, salto de 1
}

// PRIMER DIBUJADO al cargar la página
pintar();
Leé el ejemplo en tres colores
Todo lo del ejemplo cae en uno de estos tres grupos: estado (let valor — el dato), enlace (querySelector + addEventListener — las cuatro conexiones entre HTML y JS) y pintado (pintar() — el único lugar que toca el DOM). Si en tu proyecto podés señalar esas tres partes, el cableado está bien hecho.

8. Si falta una pieza, esto es lo que ves

Los errores de enlace son los más frustrantes porque no siempre tiran error en consola. Esta tabla es tu primer lugar de consulta:

Ejercicio 0 — Cablear un botón desde cero

Creá tres archivos vacíos (index.html, estilos.css, app.js) en la misma carpeta y escribí el código mínimo para que: (1) haya un botón que diga "Cambiar color", (2) al tocarlo, un <p> con un texto pase a tener fondo cian. Respetá los 4 pasos y usá una clase CSS para el color, no un estilo escrito desde JS.

Ver solución

1) HTML — los ganchos y los dos enlaces:

<link rel="stylesheet" href="estilos.css">
...
<p id="mensaje">Este texto va a cambiar de color</p>
<button id="btn-color">Cambiar color</button>
...
<script src="app.js"></script>

2) CSS — la clase que JS va a activar:

.resaltado { background: #4fd1c5; color: #06141a; padding: 8px; }

3) JS — el cableado de 4 pasos:

const mensaje = document.querySelector('#mensaje');
const boton   = document.querySelector('#btn-color');

boton.addEventListener('click', () => {
  mensaje.classList.toggle('resaltado');
});

Por qué funciona: el id es el mismo en el HTML y en el querySelector (#mensaje, #btn-color); el addEventListener es el cable que une el clic con la función; y la clase resaltado existe en el CSS con el mismo nombre, así que cuando JS la activa el navegador aplica el estilo. Si cambiás 'resaltado' por 'resaltadoo' en el JS, el botón sigue funcionando pero no se ve ningún cambio: esa es la prueba de que el enlace es por nombre, no por magia.

2 Fase 2 — Manipulación del DOM: renderizado

El DOM (Document Object Model) es la representación del HTML como un árbol de objetos que JavaScript puede leer y modificar. Vamos a usarlo para generar las tarjetas de producto en lugar de escribirlas a mano.

Método / propiedadQué hace
document.querySelector('#id')Devuelve el primer elemento que coincide con el selector CSS indicado.
document.querySelectorAll('.clase')Devuelve todos los elementos que coinciden, como una lista recorrible.
document.createElement('div')Crea un elemento HTML nuevo, todavía no visible (no está en el DOM).
elemento.appendChild(hijo) / .append(...)Inserta un elemento dentro de otro, haciéndolo visible.
elemento.textContent = "texto"Inserta texto plano de forma segura (no interpreta HTML).
elemento.setAttribute('src', url)Define un atributo HTML, típico para src de imágenes o href.
elemento.classList.add('clase')Agrega una clase CSS al elemento (así se conecta JS con tus estilos).
textContent vs. innerHTML
textContent inserta el texto tal cual, sin interpretarlo como HTML (más seguro con datos que vienen de un formulario). innerHTML interpreta etiquetas, y es necesario cuando armás una estructura completa de golpe como texto — pero nunca debería usarse con datos sin validar que vengan de un usuario desconocido, porque podría inyectar HTML/JS no deseado.

const contenedor = document.querySelector('#contenedor-productos');

  // 1. Limpiar el contenedor antes de volver a dibujar (evita duplicados)
  contenedor.innerHTML = '';

  // 2. Recorrer el array con forEach y crear una tarjeta por producto
  productos.forEach((producto) => {
    const tarjeta = document.createElement('article');

    tarjeta.classList.add('producto-card');

    const imagen = document.createElement('img');
    imagen.classList.add('producto-imagen');
    imagen.setAttribute('src', producto.imagen);
    imagen.setAttribute('alt', producto.nombre);

    const nombre = document.createElement('h3');

3 Fase 3 — Eventos e interactividad

Un sitio dinámico reacciona a lo que hace el usuario. Para eso usamos addEventListener, que "escucha" una acción (click, submit, input) y ejecuta una función cuando ocurre.

Evento / métodoCuándo se usa
'click'Botones: Agregar, Editar, Eliminar.
'submit'Cuando se envía un <form> (al tocar "Guardar").
'input'Cada tecla que se escribe en un campo de texto (ideal para búsqueda en vivo).
event.preventDefault()Evita el comportamiento por defecto del navegador (recargar la página al enviar un form).
event.targetReferencia al elemento exacto que disparó el evento (útil con varios botones iguales).
app.js — eventos de búsqueda y de formulario 
const buscador = document.querySelector('#buscador');
const formulario = document.querySelector('#form-producto');

// 'input' dispara en cada tecla: búsqueda en tiempo real
buscador.addEventListener('input', () => {
  console.log('Usuario escribió:', buscador.value);
});

// 'submit' + preventDefault: evita que la página se recargue
formulario.addEventListener('submit', (event) => {
  event.preventDefault();
  console.log('Formulario enviado sin recargar la página');
});

// event.target: identificar QUÉ botón exacto se clickeó
document.querySelectorAll('.btn-eliminar').forEach((boton) => {
  boton.addEventListener('click', (event) => {
    console.log('Se clickeó el botón dentro de:', event.target.closest('.producto-card'));
  });
});

Para que un botón "Eliminar" sepa a qué producto pertenece, guardamos el id del producto como atributo data-id en la tarjeta (tarjeta.dataset.id = producto.id), y después lo leemos con event.target.closest('.producto-card').dataset.id. Es la misma técnica de atributos data-* que vimos en la Sesión 2.

4 Fase 4 — Consumo y manejo del JSON

Con el array de productos ya renderizado y los eventos básicos funcionando, ahora tratamos el JSON como lo que es: una base de datos en memoria que podemos consultar con los métodos de array de JavaScript.

MétodoDevuelveUso típico
array.find(fn)El primer elemento que cumple la condición, o undefined.Buscar un producto por id para mostrar su detalle.
array.findIndex(fn)La posición (número) del primer elemento que cumple la condición, o -1.Ubicar un producto para reemplazarlo (Update).
array.filter(fn)Un nuevo array con todos los elementos que cumplen la condición.Filtrar por categoría, por precio, o eliminar un producto (Delete).
array.forEach(fn)Nada (undefined); solo ejecuta algo por cada elemento.Renderizar cada producto en el DOM.
consultas.js 
// Buscar UN producto puntual por id (para mostrar detalle o editar)
const producto = productos.find((p) => p.id === 3);
console.log(producto); // { id: 3, nombre: "Monitor 27 pulgadas 4K", ... }

// Encontrar la POSICIÓN de un producto (necesario para reemplazarlo)
const indice = productos.findIndex((p) => p.id === 3);
console.log(indice); // 2 (es el tercer elemento, índice 0-based)

// Filtrar por categoría

// Filtrar por rango de precio
const economicos = productos.filter((p) => p.precio < 50);

find es como buscar una persona por DNI en una fila: te quedás con la primera que coincide y dejás de buscar. filter es como pedir "todas las personas mayores de 18": te armás una fila nueva solamente con quienes cumplen la condición, sin tocar la fila original.

5 Fase 5 — CRUD completo integrado

Llegó el momento central de la sesión: vamos a construir las 4 operaciones que cualquier sistema de datos necesita. Las cuatro comparten la misma lógica: modificar el array productos y después llamar a renderizarCatalogo(productos) para que la pantalla refleje el nuevo estado.

5.1 CREATE — Agregar producto

Capturamos los valores del formulario, generamos un id único con Date.now() (devuelve la cantidad de milisegundos desde 1970: prácticamente nunca se repite), y agregamos el nuevo objeto al array con push.

crud.js — Create 
function agregarProducto(datos) {
  const nuevoProducto = {
    id: Date.now(),      // id único basado en la fecha/hora actual
    ...datos             // spread: copia nombre, descripcion, precio, stock, categoria
  };
  productos.push(nuevoProducto); // agrega al final del array
  renderizarCatalogo(productos); // vuelve a dibujar TODO el catálogo
}

5.2 READ — Leer / listar productos

Ya la cubrimos en la Fase 2 con renderizarCatalogo, y en la Fase 4 con find/filter. Es importante remarcar que toda operación CRUD termina volviendo a leer (renderizar) el array para mantener la pantalla sincronizada con los datos reales.

5.3 UPDATE — Editar producto existente

Buscamos la posición del producto con findIndex y reemplazamos ese elemento del array combinando sus datos viejos con los nuevos usando el operador spread (...).

crud.js — Update 
function editarProducto(id, datosActualizados) {
  const index = productos.findIndex((p) => p.id === id);

  if (index !== -1) {
    // Spread: mezcla el objeto viejo con los campos nuevos (los nuevos pisan a los viejos)
    productos[index] = { ...productos[index], ...datosActualizados };
    renderizarCatalogo(productos);
  } else {
    console.error('No se encontró ningún producto con id', id);
  }
}

// Ejemplo: solo cambiamos el precio y el stock, el resto queda igual
editarProducto(2, { precio: 109.99, stock: 20 });

5.4 DELETE — Eliminar producto

Pedimos confirmación con confirm() (una ventana nativa del navegador) y usamos filter para crear un array nuevo sin el producto eliminado.

crud.js — Delete 
function eliminarProducto(id) {
  const confirmado = confirm('¿Seguro que deseas eliminar este producto?');
  if (!confirmado) return; // el usuario canceló: no hacemos nada

  productos = productos.filter((p) => p.id !== id); // nuevo array sin ese producto
  renderizarCatalogo(productos);
}

eliminarProducto(5); // elimina el producto con id 5, si existe
¿Por qué eliminarProducto necesita let?
filter siempre devuelve un array nuevo; no modifica el original. Por eso, para que productos = productos.filter(...) sea válido, el array tiene que haberse declarado con let y no con const (una const no se puede reasignar).

6 Fase 6 — Integración final y refactorización

Con las 4 operaciones funcionando por separado, el último paso es organizar el código en responsabilidades claras, para que sea fácil de mantener y de extender.

ResponsabilidadContiene
DatosEl array productos (o el JSON cargado) — el "estado" de la aplicación.
LógicaLas funciones CRUD (agregarProducto, editarProducto, eliminarProducto) y de consulta (filter, find) — nunca tocan el DOM directamente, solo el array.
RenderizadoLa única función renderizarCatalogo(productos) — la única responsable de tocar el DOM.
EventosLos addEventListener que conectan clicks y formularios con las funciones de lógica.
Regla de oro
Ninguna función de lógica debería tocar el DOM directamente, y ninguna función de renderizado debería modificar el array de datos. Esta separación (a veces llamada "separación de responsabilidades") es lo que evita que un proyecto pequeño se vuelva imposible de depurar cuando crece.

Manejo básico de errores

SituaciónCómo manejarla
Producto no encontrado al editar/eliminarfindIndex devuelve -1: comprobar con if (index !== -1) antes de continuar.
Formulario con campos vacíosValidar con if (!nombre || isNaN(precio)) antes de modificar el array.
Precio o stock no numéricosisNaN(valor) detecta si algo no es un número válido tras parseFloat/parseInt.

    btnEditar.addEventListener('click', () => abrirFormularioEdicion(producto.id));

    const btnEliminar = document.createElement('button');
    btnEliminar.classList.add('btn-eliminar');
    btnEliminar.textContent = 'Eliminar';
    btnEliminar.addEventListener('click', () => eliminarProducto(producto.id));

    tarjeta.append(imagen, nombre, descripcion, precio, stock, btnEditar, btnEliminar);
    contenedor.appendChild(tarjeta);
  });
}

// ====== 4. LECTURA CON FILTROS (búsqueda + categoría combinadas) ======
function aplicarFiltros() {
  const texto = buscador.value.trim().toLowerCase();
  const categoria = filtroCategoria.value;

  const filtrados = productos.filter((p) => {
    const coincideTexto = p.nombre.toLowerCase().includes(texto);
    const coincideCategoria = categoria === 'todas' || p.categoria === categoria;
    return coincideTexto && coincideCategoria;
  });

  renderizarCatalogo(filtrados);
}

// ====== 5. CREATE ======
function agregarProducto(datos) {
  if (!datos.nombre || isNaN(datos.precio) || isNaN(datos.stock)) {
    alert('Completá todos los campos obligatorios');
    return;
  }
  const nuevoProducto = { id: Date.now(), ...datos };
  productos.push(nuevoProducto);
  aplicarFiltros();
}

// ====== 6. UPDATE ======
function editarProducto(id, datosActualizados) {
  const index = productos.findIndex((p) => p.id === id);
  if (index === -1) {
    console.error('Producto no encontrado:', id);
    return;
  }
  productos[index] = { ...productos[index], ...datosActualizados };
  aplicarFiltros();
}

// ====== 7. DELETE ======
function eliminarProducto(id) {
  if (!confirm('¿Seguro que deseas eliminar este producto?')) return;
  productos = productos.filter((p) => p.id !== id);
  aplicarFiltros();
}

// ====== 8. FORMULARIO: abrir en modo Create o Update ======
function abrirFormularioCreacion() {
  editandoId = null;
  formTitulo.textContent = 'Nuevo producto';
  formulario.reset();
  formulario.classList.add('open');
}

function abrirFormularioEdicion(id) {
  const producto = productos.find((p) => p.id === id);
  if (!producto) return;
  editandoId = id;
  formTitulo.textContent = `Editando: ${producto.nombre}`;
  document.querySelector('#input-nombre').value = producto.nombre;
  document.querySelector('#input-descripcion').value = producto.descripcion;
  document.querySelector('#input-precio').value = producto.precio;
  document.querySelector('#input-stock').value = producto.stock;
  document.querySelector('#input-categoria').value = producto.categoria;
  formulario.classList.add('open');
}

function cerrarFormulario() {
  formulario.classList.remove('open');
  formulario.reset();
  editandoId = null;
}

// ====== 9. EVENTOS: conectan la interfaz con la lógica ======
formulario.addEventListener('submit', (event) => {
  event.preventDefault();

  const datos = {
    nombre: document.querySelector('#input-nombre').value.trim(),
    descripcion: document.querySelector('#input-descripcion').value.trim(),
    precio: parseFloat(document.querySelector('#input-precio').value),
    stock: parseInt(document.querySelector('#input-stock').value, 10),
    categoria: document.querySelector('#input-categoria').value
  };

  if (editandoId === null) {
    agregarProducto(datos);
  } else {
    editarProducto(editandoId, datos);
  }
  cerrarFormulario();
});

btnNuevo.addEventListener('click', abrirFormularioCreacion);
btnCancelar.addEventListener('click', cerrarFormulario);
buscador.addEventListener('input', aplicarFiltros);
filtroCategoria.addEventListener('change', aplicarFiltros);

// ====== 10. PRIMER RENDER AL CARGAR LA PÁGINA ======

Detectá el error: código para corregir en VSC

Copiá estos fragmentos en VSC y usá las herramientas de desarrollo (F12 → Console) para encontrar los errores antes de revelar la solución.

Con errores

Ejercicio 1 — El array no se actualiza

buggy-13.js 
const productos = [
  { id: 1, nombre: "Mouse", precio: 20 },
  { id: 2, nombre: "Teclado", precio: 50 }
];

function eliminarProducto(id) {
  if (!confirm('¿Eliminar?')) return;
  productos = productos.filter((p) => p.id !== id);
  renderizarCatalogo(productos);
}

eliminarProducto(1);

🔎 Al ejecutar esto, la consola tira un error y nada se elimina. Encontrá el 1 problema.

Ver solución y explicación
  1. El array se declaró con const productos, pero dentro de eliminarProducto se intenta reasignar con productos = productos.filter(...). Una variable const nunca puede reasignarse: hay que declararla con let productos = [...].

Tip de debugging: este error aparece en la Console como Uncaught TypeError: Assignment to constant variable. — en cuanto veas "constant variable" en un mensaje de error, revisá si en algún lugar del código estás reasignando una variable declarada con const.

Con errores

Ejercicio 2 — El formulario recarga la página

buggy-14.js 
const formulario = document.querySelector('#form-producto');

formulario.addEventListener('submit', (event) => {
  const nombre = document.querySelector('#input-nombre').value;
  agregarProducto({ nombre, precio: 10, stock: 5, categoria: 'electronica' });
});

🔎 Cada vez que se hace click en "Guardar", la página se recarga por completo y se pierde todo lo agregado. Encontrá el 1 problema.

Ver solución y explicación
  1. Falta event.preventDefault() al inicio del callback. Sin esa línea, el comportamiento por defecto del navegador al enviar un <form> es recargar la página (o navegar a la URL indicada en action), destruyendo cualquier cambio hecho en memoria.

Tip de debugging: si notás que la página "parpadea" o se reinicia justo al enviar un formulario, es casi siempre un event.preventDefault() faltante en el listener de 'submit'.

Con errores

Ejercicio 3 — Editar siempre falla

buggy-15.js 
function editarProducto(id, datosActualizados) {
  const index = productos.findIndex((p) => p.id = id);
  productos[index] = { ...productos[index], ...datosActualizados };
  renderizarCatalogo(productos);
}

🔎 Esta función siempre termina editando el último producto del array, sin importar qué id se le pase. Encontrá el 1 problema (es un error muy común y difícil de ver a simple vista).

Ver solución y explicación
  1. Dentro del findIndex se escribió p.id = id (un solo signo igual, que es asignación) en vez de p.id === id (triple igual, comparación). Como una asignación siempre "devuelve" el valor asignado (y id suele ser un número distinto de cero), la condición se evalúa como verdadera para el último elemento recorrido, haciendo que findIndex devuelva el último índice.

Tip de debugging: este es uno de los bugs más silenciosos de JavaScript porque no tira ningún error en consola. La única forma de detectarlo es revisar con atención cada comparación dentro de un find/ filter/findIndex, o agregar un console.log(p.id, id) dentro del callback para ver qué se está comparando realmente.

Glosario rápido

DOM
Representación del HTML como un árbol de objetos que JavaScript puede leer y modificar.
JSON
Formato de texto para representar datos como objetos y arrays, usado como "base de datos" simulada.
CRUD
Create, Read, Update, Delete: las cuatro operaciones básicas sobre un conjunto de datos.
Evento
Una acción del usuario (click, submit, input) que JavaScript puede "escuchar" con addEventListener.
Callback
Función que se pasa como argumento a otra función, para ejecutarse en un momento posterior (ej: dentro de forEach o addEventListener).
Spread (...)
Operador que copia las propiedades de un objeto (o elementos de un array) dentro de otro nuevo.
Estado (state)
Los datos que determinan lo que se muestra en pantalla en un momento dado; en esta sesión, el array productos.
Renderizar
Generar o actualizar el HTML visible a partir de los datos actuales del estado.
