Sesión 3 — CSS: Maquetación con Flexbox

Dejamos de "ensuciar" el HTML con estilos y aprendemos a separar contenido y diseño con hojas de estilo externas. Después, ordenamos y alineamos el catálogo con CSS Flexbox: ejes, alineación, distribución y orden de elementos.

Objetivos de aprendizaje

Al finalizar esta sesión, vas a poder:

  • Explicar por qué separar el CSS del HTML en un archivo externo, y vincularlo correctamente desde <head>.
  • Escribir rutas relativas correctas para importar una hoja de estilos ubicada en cualquier carpeta o subcarpeta del proyecto.
  • Explicar la jerarquía de prioridades de CSS (cascada, especificidad y !important) para predecir qué regla "gana" cuando hay conflictos.
  • Diferenciar eje principal y eje transversal en Flexbox, y usar justify-content, align-items y flex-wrap para alinear y distribuir elementos.
  • Reordenar visualmente elementos con order sin alterar el HTML.
  • Aplicar criterios básicos de diseño web accesible e inclusivo (contraste, tamaño de fuente, tipografías legibles) en el catálogo.
  • Maquetar con Flexbox la grilla de tarjetas de producto del E-commerce, con una hoja de estilos externa correctamente organizada en carpetas.

Introducción a las hojas de estilo externas

Existen 3 formas de aplicar CSS a un documento HTML:

Tipo Dónde se escribe ¿Cuándo usarla?
Inline Directamente en el atributo style de una etiqueta: <p style="color:red"> Casi nunca en un proyecto real. Es difícil de mantener y "ensucia" el HTML.
Interna (embed) Dentro de una etiqueta <style> en el <head> del mismo documento. Prototipos rápidos o pruebas puntuales. No se reutiliza entre páginas.
Externa ✅ En un archivo .css aparte, vinculado con <link>. Siempre en proyectos reales: un solo archivo de estilos sirve para todas las páginas del sitio.
Analogía
Separar el CSS del HTML es como separar el guion de una obra de teatro del manual de vestuario y escenografía: los actores (el HTML) dicen sus líneas igual sin importar qué escenografía uses, y podés cambiar toda la escenografía (el CSS) sin reescribir una sola línea del guion. Si mezclás todo en un solo documento (estilos inline), cualquier cambio de vestuario te obliga a reescribir la obra entera.

Para vincular un archivo CSS externo se usa la etiqueta <link> dentro del <head>:

index.html (fragmento del head) 
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>TecnoStore</title>

    <!-- rel="stylesheet" le dice al navegador que ese archivo es CSS -->
    <!-- href apunta a la RUTA del archivo .css -->
    <link rel="stylesheet" href="css/style.css">
</head>
Atributos clave de <link>
rel="stylesheet" es obligatorio: indica la relación del archivo con el documento. href es la ruta al archivo. El <link> es una etiqueta "vacía" (no se cierra con </link>), igual que <img> o <meta>.

Guía: cómo acceder a un CSS ubicado en otra carpeta o subcarpeta

El valor del atributo href es una ruta relativa: describe "cómo llegar" desde el archivo que estoy escribiendo (index.html) hasta el archivo que quiero importar (style.css), recorriendo carpetas.

Estructura de carpetas de referencia

📁 ecommerce-proyecto/
├── index.html ← el archivo que hace el import
├── 📁 css/
│ └── style.css ← hoja de estilos principal
├── 📁 css/componentes/
│ └── tarjetas.css ← subcarpeta dentro de css/
├── 📁 js/
│ └── main.js
└── 📁 data/
   └── productos.json
Símbolo Significado
carpeta/archivo.css "Entrá a la carpeta carpeta y ahí buscá archivo.css" (bajar un nivel).
../ "Subí un nivel", es decir, ir a la carpeta contenedora (padre) de donde estoy.
../../ Subir dos niveles.
./archivo.css "Buscá en la carpeta actual" (el ./ es opcional, es el valor por defecto).
/archivo.css Ruta absoluta desde la raíz del sitio (se usa poco en proyectos chicos; puede fallar si el sitio no está en la raíz del dominio).

Ejemplos aplicados a la estructura de arriba

Ejemplos de rutas relativas 
<!-- Desde index.html (en la RAÍZ) hacia css/style.css -->
<link rel="stylesheet" href="css/style.css">

<!-- Desde index.html hacia una SUBCARPETA de css/ -->
<link rel="stylesheet" href="css/componentes/tarjetas.css">

<!-- Si tuviera un archivo en css/paginas/producto.html -->
<!-- y quisiera importar css/style.css, debo SUBIR un nivel: -->
<link rel="stylesheet" href="../style.css">

<!-- Y si necesitara subir DOS niveles desde una subcarpeta más profunda: -->
<link rel="stylesheet" href="../../css/style.css">
Truco para no perderte
Parate mentalmente en la carpeta donde está el archivo HTML que estás editando, y "caminá con el dedo" por el árbol de carpetas hasta llegar al archivo CSS. Cada carpeta que bajás, la escribís con /; cada carpeta que subís, la escribís con ../. Si te equivocás, el navegador no tira "error" visible: simplemente no aplica ningún estilo — por eso siempre hay que revisar la pestaña Network del Inspector para confirmar que el archivo cargó (código 200) y no falló (404).

Jerarquía de prioridades en CSS (cascada y especificidad)

Cuando dos o más reglas CSS le dicen cosas distintas al mismo elemento, el navegador necesita un criterio para decidir cuál "gana". Ese criterio se llama cascada y se resuelve, en orden, con estos 3 factores:

Orden Factor ¿Cómo funciona?
1.º Importancia (!important) Una regla marcada con !important gana casi siempre, sin importar la especificidad. Usar con muchísimo cuidado.
2.º Especificidad Un puntaje que se calcula según qué tipo de selector se usó (ver escala abajo). A mayor puntaje, más prioridad.
3.º Orden de aparición Si dos reglas tienen exactamente la misma especificidad, gana la que está escrita más abajo (la última que el navegador lee).

Escala de especificidad (de menor a mayor prioridad)

1
Selector de etiqueta (Tags) — ej: p, article, button, h1
2
Selector de clase / atributo / pseudo-clase — ej: .product-card, [type="text"], :hover
3
Selector de ID — ej: #carrito (más específico que cualquier clase)
4
Estilos inline — ej: style="color:red" directamente en la etiqueta HTML
★
!important — se salta la escala completa y gana casi siempre (usar solo como último recurso)
ejemplo-especificidad.css 
/* Especificidad baja: selector de etiqueta */
p { color: white; }

/* Especificidad media: selector de clase → ESTA GANA sobre la anterior */
.price { color: lightgreen; }

/* Especificidad alta: selector de ID → ESTA GANA sobre la clase */
#precio-destacado { color: gold; }

/* Gana SIEMPRE (salvo otro !important más específico después) */
.price { color: red !important; }
Analogía
Pensá la especificidad como rangos militares dando la misma orden: si un soldado (etiqueta p) dice "color blanco" y un capitán (clase .price) dice "color verde", se obedece al capitán. Si además aparece un general (ID #precio-destacado) diciendo "color dorado", se obedece al general. Y si en algún momento aparece una orden con !important, es como una orden directa del comandante en jefe: pisa todos los rangos anteriores.
Por qué evitar el abuso de !important
Si empezás a usar !important en todos lados para "ganarle" a otra regla, perdés el control de la cascada: al final nadie sabe qué regla realmente manda, y cada nuevo estilo se convierte en una guerra de !important contra !important. La solución profesional es escribir selectores con la especificidad justa y necesaria, no "forzar" la prioridad.

Introducción a Flexbox: ejes, alineación y distribución

Flexbox es un sistema de CSS pensado para acomodar elementos en una sola fila o una sola columna, controlando fácilmente cómo se alinean, distribuyen y ordenan. Es ideal para: menús de navegación, grillas de tarjetas de producto, y centrar contenido vertical y horizontalmente.

Analogía general
Flexbox es como organizar sillas en una fila de un cine: podés decidir si se apiñan todas al principio, se separan con el mismo espacio entre ellas, se estiran para ocupar toda la fila, o se acomodan verticalmente centradas en su propia butaca. El "contenedor" (display: flex) es la fila de butacas; los "ítems" son cada silla.

Los dos ejes de Flexbox

Eje Nombre técnico ¿Qué controla?
➡️ Horizontal (por defecto) Eje principal (main axis) La dirección en la que se acomodan los ítems por defecto (flex-direction: row).
⬇️ Vertical (por defecto) Eje transversal (cross axis) La dirección perpendicular al eje principal.

Importante: si cambiás flex-direction a column, ¡los ejes se invierten! El eje principal pasa a ser el vertical, y el transversal el horizontal.

Propiedades esenciales del contenedor

Propiedad Valores comunes Función
display: flex; — Activa Flexbox en el contenedor. Sin esto, nada de lo siguiente funciona.
flex-direction row · row-reverse · column · column-reverse Define el eje principal y el sentido de acomodo.
justify-content flex-start · center · flex-end · space-between · space-around · space-evenly Distribuye los ítems a lo largo del eje principal.
align-items stretch · center · flex-start · flex-end Alinea los ítems en el eje transversal.
flex-wrap nowrap · wrap Permite que los ítems "salten de línea" cuando no entran todos en una sola fila (clave para responsive).
gap ej: 16px Espacio uniforme entre ítems, sin necesidad de márgenes manuales.

Propiedades esenciales de cada ítem

Propiedad Función
order Cambia el orden visual de un ítem sin tocar el HTML. Por defecto todos valen 0; un valor menor se muestra antes.
flex-grow Cuánto "crece" un ítem para ocupar espacio libre extra, en proporción a los demás.
flex-shrink Cuánto se "achica" un ítem si no hay espacio suficiente.
align-self Sobrescribe el align-items del contenedor, solo para ese ítem puntual.

Diseño web accesible e inclusivo

Un catálogo bien maquetado con Flexbox también debe ser legible para todo el mundo: personas con baja visión, daltonismo, dislexia o que usan el sitio desde un celular viejo con pantalla chica. Estas son buenas prácticas mínimas que vamos a aplicar desde hoy:

  • Contraste de color suficiente entre texto y fondo (por eso este material usa modo oscuro con textos claros de alto contraste, nunca gris claro sobre blanco).
  • No depender solo del color para transmitir información (ej: un producto "sin stock" no debe indicarse solo con texto rojo; sumar un ícono o la palabra "Agotado").
  • Tamaño de fuente legible: mínimo recomendado 16px para texto de cuerpo, permitir el zoom del navegador (nunca deshabilitarlo).
  • Tipografías simples y con buen espaciado entre letras, evitando fuentes decorativas para textos largos.
  • Textos alternativos (alt) en todas las imágenes, como ya vimos en la Sesión 2.

🎨 css/style.css (Flexbox aplicado al catálogo)

css/style.css 
/* Reset mínimo para trabajar más prolijo */
* { box-sizing: border-box; margin: 0; padding: 0; }

body {
    font-family: Arial, sans-serif;
    background-color: #111;
    color: #f1f1f1;
    font-size: 16px; /* tamaño de fuente base legible (accesibilidad) */
}

/* ============================================= */
/* CONTENEDOR FLEXIBLE: la grilla del catálogo    */
/* ============================================= */
.catalogo-grid {
    display: flex;              /* activa Flexbox */
    flex-direction: row;        /* eje principal horizontal */
    flex-wrap: wrap;            /* permite pasar de línea en pantallas chicas */
    justify-content: center;    /* distribuye tarjetas centradas en el eje principal */
    align-items: stretch;       /* todas las tarjetas con la misma altura */
    gap: 20px;                  /* espacio uniforme entre tarjetas, sin márgenes manuales */
    padding: 20px;
}

/* ============================================= */
/* CADA TARJETA ES UN FLEX ITEM                   */
/* ============================================= */
.product-card {
    background-color: #1c1c1c;
    border: 1px solid #333;
    border-radius: 10px;
    padding: 16px;
    width: 240px;               /* ancho base de cada tarjeta */
    display: flex;              /* Flexbox también DENTRO de la tarjeta */
    flex-direction: column;     /* apila imagen, título, precio y botón */
    align-items: center;
    gap: 10px;
}

.product-card img {
    max-width: 100%;
    border-radius: 6px;
}

.product-card .price {
    font-weight: bold;
    color: #4fd1c5;             /* buen contraste sobre fondo oscuro */
}

.product-card button {
    margin-top: auto;           /* empuja el botón al final de la tarjeta */
    background-color: #4fd1c5;
    color: #08131a;
    border: none;
    border-radius: 6px;
    padding: 10px 16px;
    font-size: 1rem;            /* botón cómodo de tocar en celulares */
    cursor: pointer;
}

/* Responsive: en pantallas chicas, las tarjetas ocupan casi todo el ancho */
/* max-width establece el ancho máximo que puede tener un elemento */
@
@media (max-width: 768px) {
    .product-card {
        width: 100%;
        max-width: 320px;
        background-color: #00ff15;
    }
}
@media (max-width: 600px) {
    .product-card {
        width: 100%;
        max-width: 320px;
        background-color: #e70505;
    }
}

Ejercicio 1 — Vinculación de la hoja de estilos

buggy-5.html (estructura del proyecto: index.html está en la raíz, el CSS en css/style.css) 
<head>
  <meta charset="UTF-8">
  <title>Mi Tienda</title>
  <link rel="styleshet" href="style.css">
</head>

🔎 El CSS no se aplica en el navegador. Encontrá los 2 errores (uno de sintaxis, uno de ruta) que lo explican.

Ver solución y explicación
  1. El atributo dice rel="styleshet": está mal escrito, debe ser exactamente rel="stylesheet". Un typo en este valor hace que el navegador ignore el archivo silenciosamente (sin mostrar ningún error visible en pantalla).
  2. El href="style.css" apunta a la carpeta actual, pero según la estructura del proyecto el archivo real está en css/style.css (dentro de la subcarpeta css/). Debe corregirse a href="css/style.css".
Con errores

Ejercicio 2 — Flexbox y especificidad

buggy-6.css 
.catalogo-grid {
  flex-direction: row;
  justify-content: center;
  gap: 20px;
}

#catalogo-grid {
  color: red !important;
}

.product-card {
  color: white;
}

🔎 Las tarjetas no se acomodan en fila y el texto se ve rojo en vez de blanco. Encontrá 2 problemas: uno de Flexbox, otro de jerarquía de prioridades.

Ver solución y explicación
  1. Al contenedor .catalogo-grid le falta la línea display: flex;. Sin esa propiedad, flex-direction, justify-content y gap no tienen ningún efecto: Flexbox no está activado.
  2. La regla #catalogo-grid { color: red !important; } gana por dos motivos combinados: los selectores de ID tienen más especificidad que los de clase, y además usa !important, que se salta casi toda la cascada. Aunque exista un typo conceptual (mezclar selector de id con nombre de clase), si en el HTML real hay un elemento con id="catalogo-grid", esa regla le va a "ganar" al .product-card { color: white; }. La solución es eliminar el !important innecesario y no duplicar selectores de distinta especificidad para el mismo estilo.

Tip de debugging: en el Inspector, pestaña Elements, seleccioná la tarjeta y mirá el panel Styles: las reglas tachadas son las que "perdieron" la cascada, y podés ver exactamente cuál las tachó y por qué.
