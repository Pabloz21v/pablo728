Sesión 6 — CSS: Frameworks Utilitarios con Tailwind CSS

Cerramos la sección CSS con un tercer enfoque de maquetado: en vez de escribir selectores CSS propios (Sesiones 3 y 4) o usar componentes ya armados (Bootstrap, Sesión 5), Tailwind propone clases utilitarias diminutas que se combinan directamente en el HTML para construir cualquier diseño a medida.

Objetivos de aprendizaje

Al finalizar esta sesión, vas a poder:

  • Explicar el enfoque "utility-first" de Tailwind CSS y en qué se diferencia de escribir CSS propio o de usar componentes de Bootstrap.
  • Vincular Tailwind a un proyecto mediante CDN para practicar y prototipar.
  • Aplicar clases utilitarias de espaciado (p-*, m-*, gap-*) siguiendo la escala numérica de Tailwind.
  • Aplicar clases utilitarias de tipografía (tamaño, peso, alineación) directamente sobre las etiquetas HTML.
  • Aplicar clases utilitarias de color (fondo, texto, borde) usando la paleta y escala de intensidad de Tailwind.
  • Construir diseños responsivos con prefijos de breakpoint (sm:, md:, lg:) sin escribir ningún @media.
  • Decidir con criterio propio cuándo conviene CSS propio, Bootstrap o Tailwind según el proyecto.

¿Qué es el enfoque "utility-first"?

En las Sesiones 3 y 4 escribimos nuestras propias clases CSS (.product-card, .catalogo-grid) y les definimos el comportamiento en un archivo .css aparte. En la Sesión 5 usamos las clases ya armadas de Bootstrap (card, navbar), que traen varias propiedades combinadas en una sola palabra.

Tailwind CSS propone un tercer camino: miles de clases diminutas y de un solo propósito ("utilidades"), que se combinan directamente en el atributo class del HTML para lograr cualquier diseño, sin escribir casi nunca un archivo .css propio.

CSS propio (Sesiones 3-4) Bootstrap (Sesión 5) Tailwind (hoy)
Unidad de trabajo Reglas CSS completas Componentes completos (card, navbar) Micro-utilidades de un solo propósito (p-4, text-xl)
Dónde se escribe el estilo Archivo .css aparte Archivo .css del framework (no se toca) Directamente en el atributo class del HTML
Apariencia final 100% personalizada Reconocible como "sitio con Bootstrap" si no se personaliza 100% personalizada, sin aspecto "de fábrica"
Ejemplo de uso .product-card { padding: 16px; } class="card" class="p-4 rounded-xl bg-slate-800"
Analogía
Si Bootstrap es comprar una comida ya preparada (una hamburguesa completa, lista), Tailwind es más parecido a un mostrador de ingredientes sueltos (pan, carne, queso, lechuga, salsa) que vos combinás vos mismo en el momento, en el orden y cantidad que quieras, armando tu propia receta sin cocinar cada ingrediente desde cero (como sí hacías con CSS 100% propio).
No reemplaza lo anterior, lo combina
Tailwind también usa Flexbox y Grid por debajo (clases como flex o grid grid-cols-3 son atajos directos a lo que ya aprendiste en las Sesiones 3 y 4). Entender la lógica de Flexbox/Grid es lo que te permite hoy leer y predecir qué hace cada clase de Tailwind sin memorizar todo de cero.

CDN vs. instalación real de proyecto
A diferencia de Bootstrap, la forma profesional de usar Tailwind en un proyecto en producción es instalarlo como herramienta de compilación (genera un único archivo .css final, mucho más liviano). El Play CDN que usamos hoy es la variante pensada exclusivamente para aprender y prototipar: es más pesado y no se recomienda para un sitio publicado real.

Espaciados: padding y margin con escala numérica

Tailwind no permite escribir cualquier número de píxeles: usa una escala predefinida de espaciado, donde cada número representa un múltiplo de 0.25rem (4px). Esto genera consistencia visual en todo el sitio sin que el equipo tenga que ponerse de acuerdo manualmente en los valores.

Clase Valor real Prefijo según el lado
p-1 4px p = todos los lados · px/py = horizontal/vertical · pt/pr/pb/pl = un lado específico
p-2 8px
p-4 16px
p-8 32px

La misma lógica de prefijos aplica a margin, cambiando la letra inicial de p a m:

p-1
4px · 0.25rem
p-2
8px · 0.5rem
p-4
16px · 1rem
p-6
24px · 1.5rem
p-8
32px · 2rem
p-12
48px · 3rem
Analogía
Es como elegir el tamaño de un café: no pedís "187ml exactos", elegís entre chico, mediano o grande de un menú predefinido. La escala de Tailwind (1, 2, 4, 6, 8, 12...) es ese menú de tamaños de espaciado: limitado a propósito, para que todo el sitio quede visualmente coherente.
ejemplo-espaciado.html 
<!-- padding en todos los lados: 16px -->
<div class="p-4">Contenido</div>

<!-- padding horizontal 24px, vertical 8px -->
<div class="px-6 py-2">Botón</div>

<!-- margen inferior de 16px entre tarjetas -->
<article class="mb-4">Tarjeta de producto</article>

Tipografías: tamaño, peso y alineación

Categoría Clases Función
Tamaño text-sm · text-base · text-lg · text-xl · text-3xl Escala de tamaños de fuente predefinida, de menor a mayor.
Peso font-normal · font-semibold · font-bold Grosor del texto (equivalente a font-weight).
Alineación text-left · text-center · text-right Alineación horizontal del texto.

Colores: paleta y escala de intensidad

Cada clase de color de Tailwind sigue el patrón propiedad-color-intensidad. La intensidad va de 50 (casi blanco) a 950 (casi negro), en pasos de 100.

teal-400

teal-800
violet-200
violet-600
orange-200
orange-600
Clase Propiedad que afecta
bg-teal-500 Color de fondo (background-color).
text-teal-500 Color del texto.
border-teal-500 Color del borde (requiere también una clase border que active el ancho del borde).
Ojo con el contraste (conexión con la Sesión 3)
Elegir colores con Tailwind es muy rápido, pero la responsabilidad de un contraste accesible entre texto y fondo sigue siendo nuestra: por ejemplo, text-slate-400 sobre bg-slate-300 puede tener contraste insuficiente. Los criterios de diseño inclusivo de la Sesión 3 (WebAIM Contrast Checker, tamaño de fuente legible) siguen aplicando exactamente igual acá.

Breakpoints responsivos: prefijos antes de la clase

Tailwind también sigue la filosofía mobile-first (igual que Bootstrap, Sesión 5): una clase sin prefijo aplica siempre, y agregar un prefijo de breakpoint hace que esa clase sobrescriba a la anterior a partir de ese ancho mínimo.

Prefijo Ancho mínimo Ejemplo
(sin prefijo) 0px (siempre) grid-cols-1 → 1 columna en cualquier pantalla
sm: ≥ 640px sm:text-lg → texto más grande a partir de 640px
md: ≥ 768px md:grid-cols-2 → 2 columnas a partir de 768px
lg: ≥ 1024px lg:grid-cols-4 → 4 columnas a partir de 1024px
xl: ≥ 1280px xl:p-12 → más padding en pantallas muy grandes
ejemplo-breakpoints.html 
<!-- Grilla de productos 100% responsiva, SIN escribir @media -->
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-4">
    <div class="bg-slate-800 p-4 rounded-xl">Producto 1</div>
    <div class="bg-slate-800 p-4 rounded-xl">Producto 2</div>
    <div class="bg-slate-800 p-4 rounded-xl">Producto 3</div>
    <div class="bg-slate-800 p-4 rounded-xl">Producto 4</div>
</div>

<!-- Texto que crece en pantallas medianas en adelante -->
<h2 class="text-xl md:text-3xl font-bold">Catálogo</h2>

<!-- Oculto en celular, visible desde "md" -->
<p class="hidden md:block">Filtros avanzados disponibles</p>
Analogía (conexión con la Sesión 4)
grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 es exactamente el mismo concepto que repeat(auto-fit, minmax(...)) de CSS Grid puro (Sesión 4), solo que en vez de que el navegador "calcule solo" cuántas columnas entran, acá nosotros le indicamos explícitamente cuántas columnas queremos en cada rango de ancho. Son dos estrategias válidas para el mismo problema.

Resumen comparativo: las 3 formas de maquetar que vimos en la Unidad 1

Con esto cerramos la Unidad 1. Ya conocés tres enfoques distintos para resolver el mismo problema de maquetado, y podés elegir con criterio según el contexto del proyecto:

Enfoque Sesión Cuándo conviene
CSS propio (Flexbox / Grid) 3 y 4 Layouts muy personalizados, control total, proyectos donde el diseño es protagonista.
Bootstrap 5 Prototipos rápidos, paneles administrativos, formularios estándar, equipos que priorizan velocidad sobre un diseño 100% único.
Tailwind 6 Diseños a medida con velocidad de desarrollo alta, equipos que quieren evitar archivos .css enormes y difíciles de mantener.

Con errores

Ejercicio 1 — Espaciado y color

buggy-11.html 
<button class="padding-4 bg-teal rounded-md text-white">
  Agregar al carrito
</button>

<p class="text-size-xl font-bold">
  Oferta especial
</p>

🔎 El botón no tiene ni espaciado ni color de fondo, y el texto no cambia de tamaño. Encontrá los 3 problemas (todos son nombres de clase incorrectos).

Ver solución y explicación
  1. padding-4 no existe como clase de Tailwind; la clase correcta es p-4 (prefijo corto, sin la palabra completa "padding").
  2. bg-teal está incompleto: a todo color de Tailwind le falta la intensidad numérica (50 a 950). Debería ser, por ejemplo, bg-teal-500.
  3. text-size-xl no existe: la clase de tamaño de texto es directamente text-xl (sin la palabra "size" en el medio).

Tip de debugging: con las herramientas de desarrollo abiertas (F12), seleccioná el elemento y mirá el panel de estilos aplicados: si una clase escrita en el HTML no genera ninguna regla CSS visible en ese panel, es señal segura de que el nombre de la clase no existe tal cual está escrito.

Con errores

Ejercicio 2 — Breakpoints mal aplicados

buggy-12.html 
<div class="grid cols-1 md-grid-cols-2 lg:grid-cols-4 gap-4">
  <div class="bg-slate-800 p-4">Producto 1</div>
  <div class="bg-slate-800 p-4">Producto 2</div>
</div>

🔎 La grilla no se acomoda como se espera en ningún tamaño de pantalla. Encontrá los 2 problemas de sintaxis.

Ver solución y explicación
  1. cols-1 está incompleto: la clase correcta es grid-cols-1 (le falta el prefijo grid-).
  2. md-grid-cols-2 usa un guion medio para separar el breakpoint de la clase, pero Tailwind exige dos puntos: debe ser md:grid-cols-2. Sin los dos puntos, Tailwind no reconoce esa cadena como una variante responsiva y la ignora por completo.

Tip de debugging: los prefijos de breakpoint siempre llevan : (dos puntos) inmediatamente después, nunca un guion. Es uno de los errores de tipeo más comunes al empezar con Tailwind.
